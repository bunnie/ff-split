# quartz-style synchronous partitioning

Partition a flattened yosys JSON netlist at its flip flops into a pure
combinational half and a pure sequential half, mated by a small top.

For quartz (https://www.averest.org/#about_quartz) workflows where the
combinational block is characterized separately from the sync elements.

## Files

This code is reviewed and checked by hand:

- `ff_split.py` - the partitioner (stdlib only, Python 3.8+).
- `examples/` - test designs (3-FF up-counter, constant D input, 4-bit vector
  DFFs, direct flop-to-flop shift register, two clock domains), a Verilator
  testbench, and `run_example.sh` which drives everything end to end.
- `flattened_fast_mul_opt_corrected.{v,json}` - picorv32 fast-multiplier
  example (JSON produced with `read_verilog ...; proc; write_json`).

### Extra Tests

I don't fully understand these - but committed because they were used to
check the partitioning, and might be useful to someone else.

- `ff_equiv.py` - formal equivalence checker (SAT/induction) for the
  original netlist vs the split top (needs yosys on PATH). Not all examples
  were proven with this due to runtime becoming too long.
- `ff_structcheck.py` - fast constructive check: flattens both netlists
  with yosys and builds an explicit isomorphism witness (seeds: primary
  inputs + the flip-flop pairs whose cell names ff_split preserves; then
  congruence closure over combinational cells; obligations: every FF clock
  /D cone and every output bit matched).  A completed witness proves the
  mated split is structurally identical to the original - which is exactly
  the "read both into yosys and derive equivalent netlists" criterion - in
  ~9 s for the multiplier, versus the SAT search of ff_equiv.py.  Falls
  back to INCONCLUSIVE (not FAIL) on logic it cannot pair.

## How it works

The JSON input is a yosys `write_json` netlist after `proc`, so the
`always @(posedge clk) x <= y;` blocks have already become `$dff` cells
(`$dlatch` for the one level-sensitive case).  The splitter enumerates the
distinct clock wires driving those cells (`clk1`, `clk2`, ... in first-seen
order; edit `clock_name()` in ff_split.py to change the scheme), cuts every
`$dff`/$dlatch out, and emits three standalone-readable JSON files:

| file          | contents                                                     |
|---------------|--------------------------------------------------------------|
| `*_comb.json` | all original ports, all combinational cells, plus the sync interface |
| `*_sync.json` | the flip flops only, same interface                          |
| `*_split.json`| top wiring comb + sync, only the original ports exposed      |

Interface naming (identical on both halves, mirrored directions):

- `clkN` - clock wire.  A comb output only when the clock is generated by
  combinational logic (e.g. a gated clock); the primary `clk` pin stays a
  plain input and is not re-exported.
- `i_clkN_<sig>` - D-side: the signal going *into* a flip flop clocked by
  clkN (named after the driving wire, per-bit suffix for vector wires).
- `o_clkN_<sig>` - Q-side: the signal coming *out* of that flip flop.

The `_split.json` top instantiates both halves and restores constants tied
to ports (e.g. `pcpi_wait = 1'b0`) through buffer cells so yosys `flatten`
accepts it.

## Usage

```
# 1. (already done for the example) produce the input netlist:
yosys -p "read_verilog flattened_fast_mul_opt_corrected.v; proc; write_json flattened_fast_mul_opt_corrected.json"

# optional: see which wire became which clkN
python3 ff_split.py flattened_fast_mul_opt_corrected.json --module picorv32_pcpi_fast_mul --list-clocks

# 2. split (round-trips each output through yosys by default)
python3 ff_split.py flattened_fast_mul_opt_corrected.json --module picorv32_pcpi_fast_mul -o mul

# 3. quick structural check (seconds), then the formal proof
python3 ff_structcheck.py flattened_fast_mul_opt_corrected.json mul/flattened_fast_mul_opt_corrected_split.json --gold-module picorv32_pcpi_fast_mul
python3 ff_equiv.py flattened_fast_mul_opt_corrected.json mul/flattened_fast_mul_opt_corrected_split.json --gold-module picorv32_pcpi_fast_mul --mode cells
```

`mul/run_mul.sh` runs steps 2+3.  `examples/run_example.sh` runs the small examples
(3-FF up-counter, constant D input, 4-bit vector DFFs, direct flop-to-flop
shift register) through split, yosys round-trip and all three proof modes,
plus a negative control: two interface wires get crossed and the checker
must reject the result.  When Verilator is installed it also compiles both
the original and the mated split top against the same testbench and diffs
the traces -- catching things yosys's lenient net merging hides (it silently
accepts multiply-driven nets that simulators reject).

### Equivalence Checking

The equivalence proof (`ff_equiv.py`) has three modes:

- `--mode induct` (default): temporal induction (`equiv_make` +
  `equiv_induct`) over the name-matched wires after `flatten`ing both
  sides.  Full proof, independent of power-on state; cost grows with how
  much of the state the induction hypothesis has to guess.
- `--mode cells`: pair each flip flop on the gold side with its counterpart
  in the split (ff_split preserves the original `$techmap\<instance>...`
  cell names, so the pairing is exact), anchor every pair with
  `equiv_add -cell`, then `equiv_simple` followed by a shallow
  `equiv_induct`.  With all state elements anchored, most equivalence
  obligations collapse to per-cone combinational SAT at one state point -
  no induction search - and latches are handled as cells.  This is the fast
  path for the multiplier.
- `--mode bounded`: `clk2fflogic` + `miter -equiv` + `sat -seq N
  -set-init-zero` (BMC from equal all-zero power-on states).  Weaker (only
  N cycles) but initial-state-sensitive; the SAT problem is the full design
  unrolled, so it is the slowest option.

Plain combinational SAT comparison of the two flat netlists would spuriously
fail whenever power-on FF states differ, which is why no mode does it.

## Verification status

- `examples/run_example.sh`: all five designs PASS structcheck and all three formal
  modes; tampered split and swapped clock domains are rejected; original vs
  mated-split simulation traces identical (Verilator).
- `mul/run_mul.sh`: structcheck PASS on the full multiplier (~9 s:
  8783 nets, 134 FFs anchored, 8547 combinational cells matched - a
  complete isomorphism witness); randomized-stimulus simulation of the
  original vs the mated split produces identical traces, and the same
  stimulus run against a tampered split diverges (the sim has real
  discriminating power); the SAT proof runs separately at the end
  (hours-scale on this design).

## Limitations / assumptions

- Input must be post-`proc` (FFs visible as cells).  Plain `$dff`/`$dlatch`
  only; cells with resets/enables (`$adff`, `$sdff`, `$dffe`, ...) abort
  with a message telling you to fold them into the D logic (e.g. via stdcell
  mapping).
- Netlists with multiple instantiated submodules must be `flatten`ed first;
  memories are not handled.
- The original net name of each D/Q pin becomes the interface name, so a
  name like `fastmul.U2630_A1` appears verbatim (escaped to an identifier).
